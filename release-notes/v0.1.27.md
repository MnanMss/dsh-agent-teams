# v0.1.27 — Harness 0.2.1-rc.3 installation fix

Stable plugin release on npm `latest`; recommended host: Harness `0.2.1-rc.3`.

- Fix plugin-manager installation rejection on Harness `0.2.1-rc.3`. `0.1.26` declared its exact peer set up to `0.2.1-rc.2`, and the host compatibility gate reads those ranges with no fallback for an unknown runtime, so every newer host refused to load the plugin.
- Build against the complete rc.3 dependency cohort and retain rc.2 plus all previously supported hosts.
- Extend the real plugin-manager installation check, which runs without a compatibility exemption, to the rc.3 runtime gate.
- No plugin behaviour changed. The host package that evaluates plugin requirements and every package AgentTeams imports are unchanged between rc.2 and rc.3; the rc.3 delta is additive UI contracts plus two new client services.

In desktop plugin settings, install `@nanmicoder/dsh-agent-teams@0.1.27`, enable it, and restart the app if requested. For CLI:

```sh
dsh plugin --profile web add --save-exact @nanmicoder/dsh-agent-teams@0.1.27
```

See [migration evidence](../docs/harness-0.2.1-rc.3/README.md). Host versions and plugin versions are independent.
